## 初始化與啟動順序

1. **已從程式碼確認**：當 `previewStorage` 被執行時，先檢查瀏覽器是否支援 `modulepreload`；不支援時，處理現有的預載連結並以 `MutationObserver` 監看新連結，再用 `fetch` 預載。它沿用連結的 `integrity`、`referrerPolicy` 與 `crossOrigin` 對應的 credentials，並標記已處理的連結。
2. **已從程式碼確認**：呼叫 `preload-helper` 的 `t` 時，先依基準網址解析相依資源、避免重複建立連結；CSS 使用 `stylesheet` 並等待載入，其他資源使用 `modulepreload`。它傳遞 CSP nonce；失敗時送出可取消的 `vite:preloadError`，未取消則拋錯，接著才呼叫傳入的動態匯入函式。
3. **已從程式碼確認**：`webworkerAll` 靜態匯入頂點濾鏡模組及 `init`，而 `init` 又靜態匯入 CanvasPool、Filter、頂點程式與 canvas 工具；依 ES module 相依關係先評估相依模組，然後 `init` 註冊濾鏡系統及管線。`init` 不是已證實的遊戲應用程式啟動函式。
4. **已從程式碼確認**：`site.i` 在呼叫時先處理應用程式環境與本機覆寫，再以不使用快取、逾時中止的方式讀取 `/site.json`；只接受不超過 4096 字元且 `hostedFiles` 為布林值的設定，失敗時使用預設值。`translatePage` 在 body 存在時立即啟動，否則等待 `DOMContentLoaded`。
5. **推測**：這些模組可能由不同頁面或動態匯入路徑按需使用；九個檔案沒有提供完整入口呼叫鏈，無法確認它們在實際頁面之間的全域先後順序，亦不能斷言每次啟動都執行所有模組。

## 本機儲存、打包與簽章界線

- **已從程式碼確認**：`plain` 透過 `saveTransfer-BTsCILil.js` 的 `di`，分別以 `softcore`、`hardcore` 取得物件的 `save` 欄位，並以該欄位值呼叫 `localStorage.getItem` 檢查是否存在；實際儲存金鑰名稱由相依模組決定，九個指定檔案未揭露。讀取失敗時視為不存在。
- **已從程式碼確認**：`plain` 透過同一相依模組取得存檔、產生代碼、下載或複製；代碼產生路徑只處理符合條件的 softcore 存檔，若存檔模式是 `hc` 則不產生；hardcore 存在時僅顯示提示。其匯出代碼的完整封裝、密碼學及儲存格式不在此檔中。
- **已從程式碼確認**：`pack.n` 將物件壓縮為短欄位：`i`/`id`、`b`/`base`、`t`/`type`、`r`/`rarity`、`n`/`name`、`l`/`level`；可選欄位為 `m`/`mods`、`s`/`stats`、`g`/`bonus`、`d`/`defense`、`e`/`ethereal`、`k`/`sockets`、`j`/`socketed`、`q`/`count`、`f`/`forge`。稀有度以單字母代碼表示。
- **已從程式碼確認**：`mods` 項目使用 `[stat, value, flags, length]`，旗標位元代表 `implicit`、`auto`、`staff`；`stats` 與 `bonus` 的項目使用 `[stat, value, param, level]`，尾端可省略。存在 `stats` 時，打包後 `mods` 僅保留 `auto` 或 `staff` 項目。鑲嵌物品以 `j` 內的同類結構表示，但不允許再巢狀鑲嵌。
- **已從程式碼確認**：`pack.r` 限制允許的短欄位、數值、陣列長度、孔數及數量，並驗證 `forge` 的 `t`、`up`、`hf`、`h`；其中 `h` 僅驗證十六進位字串格式與長度，不能據此認定它是簽章或推導其用途。`pack.i` 將通過檢查的短欄位還原成具名欄位。
- **已從程式碼確認**：`previewStorage` 本身沒有讀寫 localStorage、資料打包、簽章或排行榜上傳；其名稱不能作為功能證據。`pack` 所示的物品打包也未顯示密鑰使用、簽章計算或排行榜傳輸。
- **推測**：物品打包結果可能被其他存檔或上傳流程使用，但在限定的九個檔案中無法確認呼叫鏈、是否納入簽章、簽章金鑰位置、排行榜請求格式或伺服器驗證方式。不可因可還原或通過本地格式檢查就推論簽章有效或排行榜會接受。此處不列出任何金鑰或密鑰值。

## DOM、畫面層級與注入風險

- **已從程式碼確認**：`plain` 把 `#own-files-plain.overlay` 加入 `document.body`，內含 `main.plain-panel`、按鈕、連結及視情況建立的唯讀 `textarea`。`surface` 把 `#frontend.hidden` 加入 `body`，其子節點依序為 Canvas 和 `.frontend-safe`；顯示時調整 `frontend-open`、`frontend-over-run`、`frontend-backdrop` 等 class，隱藏時移除。
- **已從程式碼確認**：`surface` 預設畫布座標為 800×600，直向時依容器、裝置像素比及安全區調整；畫面持續以 `requestAnimationFrame` 重繪，按鈕與文字主要繪在 Canvas，不是可供一般 DOM 文字查找的節點。畫布會處理指標、滾輪與右鍵，並有全域 `pointerup`、`keydown` 和捕獲階段的點擊處理。
- **已從程式碼確認**：非滑鼠觸碰 Canvas 後，若一秒內的 click 目標不是該 Canvas，全域捕獲監聽器可能取消並停止該 click；新一次畫布外 `pointerdown` 會清除記錄。鍵盤事件在畫面開啟、未先被取消、非重複且時間符合時交給畫面處理，處理成功則取消預設動作。
- **已從程式碼確認**：`dom.translatePage` 監看 body 子樹的節點、文字和 `title`、`aria-label`、`placeholder`、`alt`，跳過 `script`、`style`、`textarea`、`input`、`code`、`pre`、`canvas` 與 `[data-no-translate]` 的文字；輸入元件自身的指定屬性仍可翻譯，除非位於 `[data-no-translate]` 內。Canvas 像素不會被此 DOM 翻譯器翻譯。
- **推測**：工具包若把控制項注入 body，可能被頁面翻譯器改寫文字或屬性，也可能和畫面全域鍵盤、觸控後 click 抑制及佈局爭用；可用獨立容器與 `[data-no-translate]` 降低翻譯干擾，並測試觸控、焦點及按鍵傳遞。實際遮蓋次序取決於未納入範圍的 CSS、堆疊內容與執行狀態，無法由 DOM 插入次序單獨確定 `z-index`。
