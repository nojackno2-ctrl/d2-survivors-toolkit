### 資料結構

**已從程式碼確認：** 爬層物件允許 `hero,base,fold,steps`；`hero` 是 22 字元識別字。`base` 含 `h,t,c,a,n`；步驟含 `t,c,s,a,h`，可選 `x:1` 或 `p:1`，兩者不可同時存在。`fold` 含 `r,u,n,c,d,s,a,b,h`，可選 `k,j`。追加時保留最近 50 步，驗證器接受至多 64 步；`h` 是 16 位十六進位字元，以前一個雜湊與 `claim/step/death/replay/fold` 等識別字串計算。`x` 與 `p` 對應雜湊分支 `death` 與 `replay`；其餘短欄位的業務意義未完全確認。

**已從程式碼確認：** 生命鏈為 `base:{h,n}`、可選 `fold:{n,h}`、`steps`。事件包含 `k:i,t,a,h`、`k:b,w,a,h`、`k:e,e,a,h`；結束值 `e` 限 `c,x,d`，`w` 符合 `hc-<難度>:<幕或cows>` 格式。最多保留 96 個步驟；鏈以 `d2s-life/1` 與前一雜湊計算。`i/b/e` 內部雜湊標籤依序為 `in/act/end`；`e` 三個值的完整業務語意仍待呼叫端確認。

**已從程式碼確認：** 角色提交基本欄位為 `v,player,name,build,class,level,xp,life`，可選 `mark` 為 `edited` 或 `restored`；特定驗證另外接收 `ticket` 或 `fell`。`fell` 欄位有 `difficulty,tier,act,side,at,by,skill,end`；`side` 可為 `cows`、`tristram`，`end` 可為 `startOver`。角色等級驗證範圍 1–99；未知欄位會被拒絕。

- **已從程式碼確認：** 回報可能包含遊戲呼叫端提供的執行狀況、裝備、診斷與截圖；佇列與更新已讀狀態各用獨立的 `localStorage` 鍵。**推測：** 工具包清理儲存空間或匯出診斷時應避免誤刪待送回報，並留意使用者選擇分享的資訊。
